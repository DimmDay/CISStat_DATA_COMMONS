## 1. СТАТУС
Accepted
Настоящее архитектурное решение является обязательным для всех подсистем, сервисов и участников проекта CIS Data Commons.
Отклонение от данного решения допускается исключительно на основании нового Architecture Decision Record, утвержденного Architecture Review Board.

## 2. КОНТЕКСТ
Проект CIS Data Commons создается как единая цифровая платформа официальной статистики государств – участников СНГ.
Платформа объединяет множество взаимосвязанных компонентов:
- пользовательский портал;
- ПАК ИАП;
- ЕИАС;
- СУЗ-СОД;
- CISStat TS Analysis;
- API Platform;
- Knowledge Graph;
- Metadata Registry;
- Data Lakehouse;
- AI Platform;
- Semantic Search;
- внешние источники данных;
- международные статистические стандарты (SDMX, DDI, XBRL, SIMS, ESMS, ESQRS и др.).

В традиционной практике репозиторий рассматривается преимущественно как средство хранения исходного кода. Такой подход не обеспечивает необходимый уровень прослеживаемости, повторного использования знаний и управления архитектурой для платформы данного масштаба.

Проект требует единого пространства, в котором будут храниться и связываться между собой все инженерные артефакты жизненного цикла системы.

## 3. ПРОБЛЕМА
Отсутствие единого архитектурного пространства приводит к следующим рискам:
- дублирование информации;
- расхождение документации и реализации;
- потеря архитектурных решений;
- отсутствие трассируемости требований;
- сложность анализа влияния изменений;
- зависимость знаний от отдельных специалистов;
- невозможность полноценного использования AI-ассистентов и интеллектуального поиска.

Для платформы межгосударственного уровня такие риски являются неприемлемыми.

## 4. РЕШЕНИЕ
Принято решение рассматривать репозиторий CIS Data Commons как Enterprise Knowledge System (EKS).
Репозиторий является единым достоверным источником информации (Single Source of Truth) обо всех архитектурных, организационных, нормативных и программных артефактах платформы.

Репозиторий включает, но не ограничивается следующими категориями объектов:
- стратегия;
- архитектура;
- требования;
- нормативные документы;
- архитектурные решения (ADR);
- предложения по изменениям (RFC);
- модели данных;
- метаданные;
- онтологии;
- граф знаний;
- спецификации API;
- программный код;
- инфраструктурные описания;
- тесты;
- эксплуатационная документация;
- реестры решений;
- матрицы трассируемости.

Все указанные объекты рассматриваются как равноправные элементы единой корпоративной базы знаний.

## 5. АРХИТЕКТУРНЫЕ ПРИНЦИПЫ РЕШЕНИЯ
В рамках настоящего ADR устанавливаются следующие обязательные принципы.

### 5.1 Repository as Enterprise Knowledge System
Репозиторий является корпоративной системой управления знаниями.

### 5.2 Repository as Digital Twin
Репозиторий представляет цифровой двойник архитектуры платформы.
Любое изменение платформы должно иметь отражение в репозитории.

### 5.3 Single Source of Truth
Каждый класс информации имеет единственный авторитетный источник хранения.

### 5.4 Traceability by Design
Все артефакты должны иметь двустороннюю прослеживаемость.

### 5.5 Semantic by Design
Все объекты должны обладать семантическим описанием и постоянным идентификатором.

### 5.6 Machine Readable by Design
Артефакты должны быть пригодны как для восприятия человеком, так и для автоматизированной обработки программными средствами и AI-агентами.

## 7. ПОСЛЕДСТВИЯ ПРИНЯТИЯ РЕШЕНИЯ

Положительные
- единое пространство знаний проекта;
- полная прослеживаемость жизненного цикла;
- снижение архитектурного долга;
- независимость проекта от конкретных подрядчиков;
- возможность интеллектуального поиска;
- готовность к интеграции с AI и MCP;
- автоматизация анализа влияния изменений;
- повышение качества архитектурного управления.

Потенциальные ограничения
- увеличение требований к дисциплине ведения документации;
- необходимость автоматизации контроля связей между артефактами;
- увеличение объема архитектурной документации.

Указанные ограничения считаются приемлемыми с учетом стратегических целей проекта.
