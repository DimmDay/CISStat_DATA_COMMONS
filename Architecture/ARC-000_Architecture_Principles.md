## Глава 1. Purpose
Определяет назначение документа.
Не просто "описание принципов", а:

Архитектурные принципы являются обязательными правилами проектирования, разработки, эксплуатации и развития платформы CIS Data Commons. Любое архитектурное решение (ADR), модель данных (DM), API, онтология, компонент инфраструктуры или пользовательский интерфейс должны соответствовать данным принципам либо содержать документированное обоснование отклонения.

## Глава 3. Architecture Vision
Что мы строим:

CIS Data Commons представляет собой единую цифровую платформу статистических знаний государств — участников СНГ, обеспечивающую публикацию, интеграцию, семантическое описание, поиск, анализ и машинное использование официальной статистической информации на основе открытых международных стандартов и графа знаний.

## Глава 4. Principle Catalogue
Каждый принцип - полноценный архитектурный объект.
Каждый принцип имеет единую структуру:

  ARC-00X
  - Название
  - Статус
  - Обоснование
  - Проблема
  - Принцип
  - Следствия
  - Архитектурные ограничения
  - Влияние на проектирование
  - Связанные документы
  - Связанные требования
  - Связанные ADR
  - Связанные стандарты

Это позволит автоматически строить граф знаний.

### Каталог принципов

1. ARC-001
Everything is a Knowledge Object (EKO)
Любой объект платформы рассматривается как объект знаний.

2. ARC-002
Metadata First
Метаданные создаются раньше данных.

3. ARC-003
Semantic by Design
Семантика проектируется одновременно с моделью данных.

4. ARC-004
Knowledge Graph First
Связи между объектами являются частью архитектуры.

5. ARC-005
API First
Любая функция доступна через API.

6. ARC-006
Headless Platform
Интерфейс отделен от бизнес-логики.

7. ARC-007
Infrastructure Agnostic
(вместо Cloud Native)

Поддерживается:
- On-Premises;
- Private Cloud;
- Government Cloud;
- Public Cloud;
- Hybrid.

8. ARC-008
AI Native
Платформа проектируется с учетом работы интеллектуальных агентов, MCP и RAG.

9. ARC-009
Persistent Identifiers
Любой объект имеет постоянный идентификатор.

10. ARC-010
Everything is Traceable
Любое изменение должно иметь трассируемость.

11. ARC-011
Open Standards First
- SDMX
- DDI
- XBRL
- RDF
- OWL
- SHACL
- Schema.org
- OpenAPI
- JSON-LD

12. ARC-012
Security by Design
Безопасность проектируется с самого начала.

13. ARC-013
Interoperability by Design
Совместимость между национальными статистическими системами и международными организациями закладывается в основу архитектуры.

14. ARC-014
No Vendor Lock-In
Отсутствие зависимости от конкретного поставщика технологий или облачной инфраструктуры.
Архитектура платформы не должна содержать критических зависимостей от конкретного поставщика программного обеспечения, облачной инфраструктуры или проприетарных сервисов, если существуют зрелые открытые стандарты или переносимые альтернативы.
Это означает:
- использование PostgreSQL вместо облачных СУБД с уникальными API;
- OpenSearch вместо сервисов поиска, доступных только у одного провайдера;
- Keycloak или совместимые OIDC-провайдеры вместо облачных IAM-сервисов;
- MinIO (S3-совместимое API) вместо зависимости от конкретного объектного хранилища;
- Kubernetes API как единый слой оркестрации независимо от дистрибутива.

15. ARC-015
Repository as Enterprise Knowledge System
Репозиторий GitHub является не только системой управления версиями, но и корпоративной системой управления архитектурными знаниями, обеспечивающей хранение, трассируемость и взаимосвязь всех Knowledge Objects.
