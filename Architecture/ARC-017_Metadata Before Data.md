# ARC-017 — Metadata Before Data
Отвечает на вопрос «что является обязательным условием существования данных?».

# 1. Purpose

Настоящий принцип устанавливает обязательное требование платформы CIS Data Commons:

**Никакие статистические данные не могут существовать, публиковаться, обмениваться или использоваться без соответствующих метаданных.**

Метаданные являются первичным архитектурным активом платформы и определяют смысл, происхождение, качество, структуру и правила использования данных.

---

# 2. Problem Statement

Статистические данные без метаданных приводят к:

- неоднозначной интерпретации показателей;
- невозможности автоматической интеграции;
- нарушению сопоставимости данных;
- потере информации о происхождении;
- невозможности машинной обработки;
- невозможности повторного использования;
- снижению доверия к официальной статистике.

Для международной статистической платформы подобная ситуация является недопустимой.

---

# 3. Principle Statement

Любой Dataset, Indicator, Observation, Time Series, API, Dashboard или аналитический сервис должен сопровождаться машиночитаемыми метаданными до публикации данных.

Метаданные рассматриваются как самостоятельные Knowledge Objects и управляются независимо от данных.

---

# 4. Metadata Categories

Платформа поддерживает следующие категории метаданных.

## Structural Metadata

Описание структуры данных:

- SDMX Data Structure Definition;
- DDI Variable;
- Dimensions;
- Measures;
- Attributes;
- Code Lists;
- Classifications.

---

## Reference Metadata

Описание содержания и методологии:

- SIMS;
- ESMS;
- ESQRS;
- методики расчета;
- определения показателей;
- единицы измерения;
- статистические классификации.

---

## Administrative Metadata

Описание управления:

- владелец;
- ответственный орган;
- лицензия;
- права доступа;
- жизненный цикл;
- версии;
- даты публикации.

---

## Technical Metadata

Описание технических характеристик:

- формат;
- схема сериализации;
- API;
- MIME Type;
- контрольные суммы;
- URI.

---

## Semantic Metadata

Описание семантики:

- RDF;
- OWL;
- Schema.org;
- Knowledge Graph;
- Ontology.

---

## Provenance Metadata

Описание происхождения:

- источник данных;
- процесс формирования;
- преобразования;
- версии;
- дата обновления;
- качество данных.

# 6. Metadata as Knowledge Objects

Каждый объект метаданных является самостоятельным Knowledge Object.

Например:

Knowledge Object
│
├── Dataset
├── Indicator
├── Time Series
├── SDMX Data Structure
├── DDI Variable
├── SIMS Report
├── ESMS Report
├── ESQRS Report
├── Code List
├── Classification
└── Metadata Profile

Все они обладают:

- собственной идентичностью;
- версиями;
- жизненным циклом;
- отношениями;
- URI;
- семантическим описанием.

---

# 7. Mandatory Metadata Requirements

До публикации статистических данных должны существовать:

- определение показателя;
- методика расчета;
- единица измерения;
- классификация;
- временная характеристика;
- пространственная характеристика;
- информация о качестве;
- сведения об источнике;
- правила обновления;
- лицензия.

При отсутствии хотя бы одного обязательного элемента публикация запрещается.

---

# 8. Supported Metadata Standards

Платформа должна поддерживать:

- SDMX 3.x;
- DDI Lifecycle;
- SIMS;
- ESMS;
- ESQRS;
- DCAT;
- RDF;
- OWL;
- SKOS;
- Dublin Core;
- Schema.org;
- PROV-O.

Поддержка дополнительных стандартов осуществляется посредством расширений.

---

# 9. AI Readiness

Метаданные должны быть пригодны для автоматической обработки интеллектуальными агентами.

Каждый объект обязан иметь:

- машиночитаемое описание;
- семантические связи;
- глобальную идентичность;
- ссылки на онтологию;
- связи в Knowledge Graph.

---

# 10. Architecture Consequences

Применение настоящего принципа обеспечивает:

- единое описание статистических данных;
- автоматическую интеграцию;
- интероперабельность;
- совместимость со стандартами международной статистики;
- поддержку Linked Data;
- построение Knowledge Graph;
- эффективную работу AI-сервисов;
- долгосрочную сопровождаемость платформы.

---

# 11. Compliance Requirements

Каждый Dataset должен иметь ссылки на:

- соответствующую онтологию (ONT-*);
- структурную модель (DM-*);
- профиль метаданных;
- классификаторы;
- показатели качества;
- сведения о происхождении.

Отсутствие обязательных метаданных является нарушением архитектурных принципов платформы.

---

# 12. Exceptions

Исключения допускаются исключительно:

- при миграции исторических данных;
- при аварийной публикации;
- по решению Architecture Review Board.

Каждое исключение оформляется отдельным ADR.

---

# 13. Rationale

Настоящий принцип реализует фундаментальную идею платформы:

**Метаданные являются не приложением к данным, а их обязательной архитектурной основой.**

Любой статистический показатель существует только в контексте своих определений, методологии, классификаций, ограничений применимости, происхождения и качества.

Следовательно, объектом управления платформы являются не только данные, но и знания о данных.

# 15. Compliance Checklist

Перед публикацией любого набора данных необходимо подтвердить:

- [ ] Создан профиль метаданных.
- [ ] Определена онтология.
- [ ] Определена структура данных.
- [ ] Созданы классификаторы.
- [ ] Определены показатели качества.
- [ ] Определены сведения о происхождении.
- [ ] Создано машиночитаемое описание.
- [ ] Обновлен Knowledge Graph.
- [ ] Выполнена валидация соответствия международным стандартам.
